# Financial & Technical Translation Integrity Rules

## 1. The Numeral & Token Protection System (`translator.py`)

### The Neural Translation Trap
Neural Machine Translation (NMT) and Large Language Models (LLMs) frequently corrupt numbers, codes, and acronyms in technical/financial texts:
- Converting Western Arabic numerals (`75`) into Eastern Arabic-Indic numerals (`٧٥`) inconsistently.
- Inverting decimal separators (`8.6` -> `8,6` or `.6 8`).
- Hallucinating or repeating XML placeholder tags (e.g., `<b1>` turned into `<1 b>`, `<b 1>`, or repeating indefinitely).
- Translating financial acronyms phonetically or literally (e.g., `QR` -> `كرو`, `QCBRR` -> `سعر إعادة شراء مصرف قطر المركزي` in tight table cells).

### The Solution: Curly-Bracket Placeholders (`_protect_numerals`)
Before text is sent to the translation engine, all numbers, equations, codes, and acronyms are substituted with numbered curly bracket tokens `{0}`, `{1}`, `{2}`:

```python
def _protect_numerals(text: str) -> tuple[str, dict[str, str]]:
    mapping = {}
    counter = [0]
    
    def _replacer(match):
        original = match.group(0)
        placeholder = f"{{{counter[0]}}}"
        mapping[placeholder] = original
        counter[0] += 1
        return placeholder
    
    protected = _NUMERAL_PATTERN.sub(_replacer, text)
    return protected, mapping
```

### Protection Pattern Priority:
1. **Parenthetical Mixed Tokens**: `(2018=100)`, `(QCBRR)`, `(NDS3)`, `(QR-mn)`
2. **Equations with Surrounding Context**: `2018=100`, `2018 = 100`
3. **Compound Numeric References**: `2-1`, `Chart 4-4`, `7-3`
4. **Financial / Statistical Acronyms**: `QCBRR`, `QCBLR`, `QCBDR`, `AOIR`, `QMR`, `NDS3`, `CPI`, `PPI`, `GDP`, `FISIM`, `Y-o-Y`, `Q-o-Q`, `RHS`, `USD`, `QR`
5. **Formatted Numbers & Percentages**: `75`, `75.3`, `1,200,000.5`, `8.6%`, `-3.2`, `+4.5`

### Restoration & Spacing Normalization (`_restore_numerals`):
After translation, tokens are replaced back with their original values, with robust fallback regex to handle instances where models add interior spaces `{ 0 }` or convert brackets `<0>`.

Post-restoration cleanup ensures clean spacing between Arabic letters and digits/Latin letters:
```python
text = re.sub(r'(\d)([\u0600-\u06FF])', r'\1 \2', text)
text = re.sub(r'([\u0600-\u06FF])(\d)', r'\1 \2', text)
text = re.sub(r'\s+([,.:;!?،؛])', r'\1', text)
```

## 2. Pure Passthrough Detection (`_is_pure_passthrough`)

Many table cells and chart labels contain solely numbers, years, percentages, or short financial codes:
- `"75"`, `"1,200,000"`, `"-3.2"`, `"+4.5%"`
- `"2020  2021  2022"` (Table year header rows)
- `"Q1 2022"`, `"(2018=100)"`
- `"QCBRR"`, `"bps"`

Sending these cells to a neural translation model wastes inference time and risks hallucination. If a cell matches `_PURE_PASSTHROUGH_PATTERN` or `_KNOWN_CODES`, the translation model is completely bypassed, returning the original text instantly.

## 3. Financial Terminology Normalization (`il_translator.py`)

After translation, `_normalize_arabic_output()` executes automated rule-based corrections:

### Currency Standardization
- `كرو` (a common phonetic mistranslation of `QR`) -> `ريال قطري`
- `مليارات الكرو` -> `مليارات الريالات القطرية`
- `QR 250,661 million` -> `250,661 مليون ريال قطري`
- `208.7 QR billion` -> `208.7 مليار ريال قطري`

### Basis Points (bps)
- `50 bps` / `نقاط أوروبية` / `نقاط أرضية` -> `50 نقطة أساس`

### Petroleum Sector Terminology
- `غير الزيت` / `الزيت غير` -> `غير النفط`
- `قطاع الزيت` / `القطاع الزيتي` -> `قطاع النفط`
- Standalone `oil` -> `النفط`

### Structural References
- `CHAPTER 03` -> `الفصل 03`
- `Chart 7-1` / `الشريط 7-1` -> `المخطط 7-1`
- `Table 2-1` -> `الجدول 2-1`

### Acronym BiDi Protection
Latin parenthetical acronyms are wrapped with the Unicode Left-to-Right Mark (`\u200E`) to prevent parenthesis inversion:
```python
text = re.sub(r'\([A-Z0-9]{2,}\)', lambda m: f'\u200E{m.group(0)}\u200E', text)
```

## 4. Percent Formatting & Punctuation BiDi Locking (RLM `\u200F`)

### Percent Formatting
- Western `%` is converted to the Arabic percent sign `٪` (`\u066A`).
- Errant spaces and periods generated by Seq2Seq models are cleaned up:
  - `"8.6 .٪"` -> `"8.6٪."`
  - `".٪ 8.6"` -> `"8.6٪."`

### Punctuation BiDi Locking
In bidirectional Unicode text, neutral characters (like periods `.`, colons `:`, or exclamation marks `!`) at the end of an Arabic sentence that immediately follow a digit, an Arabic percent sign, or a Latin word will jump to the right edge of the sentence instead of remaining on the left.

To lock trailing punctuation firmly to the left side of the Arabic sentence, the Right-to-Left Mark (RLM `\u200F`) is appended:
```python
text = re.sub(
    r'([\d\u066A%A-Za-z\)\u200E])\s*([.:;!؟])\s*$', 
    lambda m: f"{m.group(1)}{m.group(2)}\u200F", 
    text
)
```
- Example: `"بلغ معدل التضخم 8.6٪."` -> becomes `"بلغ معدل التضخم 8.6٪.\u200F"`, ensuring the period displays at the left margin.

## 5. Technical & Banking Standards Protection (IBAN & SWIFT)

For dense financial regulations, payment systems, and central banking standards (e.g. QCB IBAN Standards `13-193.pdf`), additional protections are enforced:

### SWIFT / BIC Code Passthrough
- **Regex**: `^[A-Z]{4}[A-Z]{2}[A-Z0-9]{2}(?:[A-Z0-9]{3})?$` (e.g. `ABQQQAQAXXX`, `BBMEQAQXXXX`, `QNBAQAQAXXX`).
- **4-Letter Bank Identifiers**: `QNBA`, `CBQA`, `DOHB`, `QISB`, `ABQQ`, `QIIB`, `ARAB`, `MSHQ`, `IBOQ`, `BBME`, `SCBL`, `UNIL`, `BNPA`, `MAFR`, `KLJI`, `BRWA`, `QIDB`.
- Bypasses translation models completely to prevent phonetic transliteration (e.g. `ABQQQAQAXXX` being translated as `قيبقواق XXX`).

### Alphanumeric Account Strings & IBANs
- **IBAN Pattern**: `^[A-Z]{2}\d{2}[A-Z0-9]{11,30}$` (e.g. `QA00SCBL000000000001375025601`).
- **BBAN Pattern**: `^[A-Z0-9]{15,35}$` with mixed alphanumeric characters (e.g. `SCBL000000000001375025601QA00`).
- Protected as atomic tokens in `_NUMERAL_PATTERN` and pure passthrough in `_is_pure_passthrough`.

### Arithmetic Equations & Division Formulas
- Division formulas: `\b\d+\s*[/÷]\s*\d+\s*(?:=\s*\d+)?\b` (e.g. `281211210/97 = 62`, `502560126/97 = 22`).
- Modulo standards: `\b(?:MOD\s*\d+(?:-\d+)?|ISO(?:/IEC)?\s*\d+(?:-\d+)?)\b` (e.g. `MOD 97-10`, `ISO/IEC 7064`).
- Captures formulas as atomic `{0}` placeholders, preventing them from being fragmented across line breaks or inverted by BiDi across the slash `/`.

### Contact Communications Metadata
- Standardizes contact headers:
  - `Tel : +974 44456371` -> `الهاتف: +974 44456371` (prevents hallucinating `التلفزيون` / "Television").
  - `Fax : +974 44430382` -> `الفاكس: +974 44430382`.
  - `E-Mail : ...` -> `البريد الإلكتروني: ...`.

## 6. Table of Contents (TOC) Dotted Leader Lines (`_TOC_LEADER_PATTERN`)

### Problem
In Tables of Contents, entries connect section titles to page numbers via runs of dotted leader characters (e.g. `1. Introduction ................................................................................................. 1306`).
- Seq2Seq translation models (MarianMT, NLLB) degrade into repetition loops or output broken curly brackets (`}}}}.مقدمة}}}`) when exposed to runs of 40–100 consecutive dots.
- Post-translation cleanup regexes previously collapsed consecutive dots (`[. 。…，]{20,}`) into a single period `.`, completely destroying leader lines in the Arabic output.
- Furthermore, because Arabic translated titles differ in horizontal width from English titles, reusing static dot counts caused entries to exceed box widths and wrap page numbers onto line 2.

### Solution & Pipeline Architecture
1. **Isolated Title Translation in `il_translator.py`**:
   - Detects TOC entries using `_TOC_LEADER_PATTERN = re.compile(r'^(.*?)\s*(\.{4,})\s*(\d+)\s*$')`.
   - Sends **only the title string** to the translation engine (e.g. `Introduction` -> `المقدمة`).
   - Leader dots and page numbers bypass the neural engine completely and are reassembled verbatim.
2. **Leader Line Protection from Collapsing**:
   - `re.sub(r"[. 。…，]{20,}", ".", text)` is bypassed whenever a line matches a leader sequence (`\.{4,}\s*\d+`).
3. **Dynamic Typesetting Leader Resizing in `typesetting.py`**:
   - When wrapping tokens in `_layout_typesetting_units`, the engine detects leader dot tokens (`all(u.unicode == '.') and len >= 4`) followed by page numbers.
   - Dynamically recalculates the exact number of dot glyphs required:
     ```python
     avail_for_dots = avail - current_line_w - pnum_w - (space_width * 3)
     needed_dots = int(avail_for_dots / dot_w)
     ```
   - Automatically shrinks dots for wider Arabic titles or expands dots for shorter titles.
   - Guarantees that the TOC entry **always fits on a single line**, with the title right-aligned at `box.x2`, the page number left-aligned at `box.x`, and dots filling the middle space.

## 7. Multi-Sentence Paragraph Translation (`_translate_with_line_preservation`)

### Problem: Seq2Seq Attention Truncation in Long Paragraphs
In macro-economic and central bank bulletins, paragraphs often span 3–5 dense sentences (500–900 characters) with repeated technical terms, years, and percentages.
- When fed into sequence-to-sequence neural translation models (e.g. Meta NLLB-200, MarianMT) as a single monolithic block, beam search and attention mechanisms frequently truncate generation after the second sentence, dropping the trailing sentences completely.
- If the dropped sentences contain shielded tokens (such as `(Chart 2-1)` or a repeated year `2022`), the missing tokens trigger restoration verification errors, resulting in the entire paragraph aborting and falling back to raw English.

### Solution: Sentence-Level Splitting
In `_translate_with_line_preservation` in `il_translator.py`:
- Flowing body text paragraphs containing multiple sentences and exceeding 150 characters are automatically split at sentence boundaries:
  ```python
  sentences = [s.strip() for s in re.split(r'(?<=[.!?])\s+', normalized_text) if s.strip()]
  if len(sentences) > 1 and len(normalized_text) > 150:
      translated_sentences = [
          self.translate_engine.translate(s, rate_limit_params=rate_limit_params)
          for s in sentences
      ]
      return " ".join(translated_sentences)
  ```
- **Benefits**:
  1. Each sentence is translated with focused attention and zero trailing truncation.
  2. Numbers, percentages, acronyms, and chart references are restored with 100% precision.
  3. Short single-sentence paragraphs and titles continue to translate as single atomic units.

## 8. Byte-Identity Verification & Graceful Fallback (`_restore_numerals`)

### Multi-Tiered Verification
In `_restore_numerals` (`translator.py`):
1. **Critical Banking Codes (SWIFT / BIC / IBAN)**:
   - For tokens matching `_SWIFT_BIC_PATTERN` or `_IBAN_PATTERN`, strict byte-identity is enforced:
     ```python
     if is_critical and actual_count < expected_count:
         raise AssertionError(
             f"Byte-identity check failed! Expected at least {expected_count} occurrence(s) "
             f"of critical banking code '{original_token}'..."
         )
     ```
   - Guarantees zero byte corruption of banking codes (e.g. preventing `BBMEQAQXXXX` from becoming `BBMEOAOXXXX`).
2. **Natural Language Numerals & Terms**:
   - For general numbers (e.g. `2022`, `4.7`), percentages, or terms that an NMT engine may idiomatically condense:
   - Logs a diagnostic warning (`logger.warning`) without raising an unhandled exception.
   - **Guarantees zero dropped translations**: The paragraph is always rendered in full Arabic rather than rolling back to raw English.
